# what-did-i-say

답변이 끝나면 "방금 무엇을 요청했는지 + 언제 요청했는지"를 입력창 바로 아래 띠에 박스로 보여주고,
`/wdis N`으로 최근 N건을 조회하는 Claude Code 플러그인.

## 동작 예시

Claude가 답변을 끝내고 입력을 기다리는 동안, 입력창 바로 아래(`? for shortcuts` 힌트 줄 자리) 띠에 어두운 단색 박스(#2b2b2b)가 뜬다.
첫 줄은 요청 시각(KST 고정, 한글 요일), 다음 줄부터 요청 내용이다.

```
  2026-10-07 (수) 14:32
  파서 필터 규칙 정리해줘
```

- 답변 중이거나 백그라운드 에이전트가 도는 동안에는 숨는다 (에이전트까지 모두 끝나야 보인다). 글자를 치는 중에는 그대로 보인다.
- `/compact` 직후에는 띠를 비우고, 다음 요청부터 다시 표시한다 (자동 compact·서브에이전트 compact·거부된 compact는 그대로 둔다).
- 요청은 줄바꿈을 유지해 **최대 5줄(빈 줄 포함)·400자**까지 보이고, 넘치면 끝에 `…`을 붙인다.
- 사람이 직접 입력한 요청만 기록한다 (백그라운드 작업 알림·예약 작업·다른 세션·플러그인이 보낸 프롬프트는 제외). 다른 훅이 막은 프롬프트도 기록하지 않는다.
- 띠를 쓰는 다른 플러그인(예: cache-necromancer 카운트다운)이 있으면 그 띠 위에 붙는다. 엔진 힌트 줄은 늘 맨 아래에 남는다.

`/wdis 3` — 시간 오름차순으로 표시되며, `[1]`이 가장 최근 요청이다.

```
[3] 14:20 (25분 전) | 훅 등록 형식 확인해줘
[2] 14:32 (12분 전) | 파서 필터 규칙 정리해줘
[1] 14:44 (방금) | 테스트 케이스 추가해줘
```

오늘이 아닌 요청에는 날짜가 함께 표시된다.

```
[3] 08-08 23:10 (15시간 전) | 슬러그 규칙 실측해줘
```

## 설치

### 로컬 시험 (세션 한정)

플러그인 디렉터리를 지정해 Claude Code를 실행한다. 전역 설정을 건드리지 않고 해당 세션에만 로드된다.

```bash
claude --plugin-dir /절대/경로/what-did-i-say
```

세션 안에서 `/help` 또는 `/plugin`에 `wdis` 커맨드가 보이면 로드된 것이다.

### 마켓플레이스

```bash
/plugin marketplace add token-keeper/plugins
/plugin install what-did-i-say@token-keeper
```

설치 후 **새 chat 세션** 부터 적용 (Claude Code settings hot-reload 안 함).

## 사용법

| 동작 | 방법 |
|---|---|
| 자동 표시 | 설치만 하면 답변이 끝날 때마다 입력창 아래 띠에 마지막 요청이 표시된다 |
| 직전 요청 조회 | `/wdis` (기본 1건) |
| 최근 N건 조회 | `/wdis 3` |

- **조회는 LLM 턴을 쓰지 않는다** — `UserPromptExpansion` 훅이 `/wdis`를 가로채 결과를 터미널에 즉시 표시하므로 컨텍스트도 소비하지 않는다.
- N이 숫자가 아니거나 1 미만이면 1건으로, 10을 초과하면 10건으로 보정하고 사유를 한 줄 안내한다.
- 다른 플러그인과 커맨드 이름이 겹치면 전체 이름 `/what-did-i-say:wdis`를 쓴다.
- 조회 결과에 `/wdis` 자신은 포함되지 않는다.

## 요구사항

- Node.js 18.17 이상 (`/wdis` 조회용, 외부 의존성 없음, stdlib만 사용)
- **띠 박스(자동 표시)는 Claude Code v2.1.286 이상**에서 동작한다 (mods = 함수 훅 플러그인, `hooks/hooks.json`의 `modules` 항목으로 로드).
  - **v2.1.200~v2.1.241 에서는 자동 표시가 없고 `/wdis` 조회만 동작한다.** `modules` 키는 오류 없이 무시되고 `/wdis` 훅은 그대로 로드된다 (v2.1.200 이상에서 실측, 그 미만은 미확인).
  - v2.1.242~v2.1.285는 mods 기능이 서버 롤아웃 플래그 뒤에 있어 환경에 따라 띠가 보일 수도 있다 (플래그가 켜진 환경은 실측하지 못한 추정).
  - 근거: 2026-10-07 격리 설정(`CLAUDE_CONFIG_DIR`)으로 v2.1.200·v2.1.241·v2.1.242~v2.1.286 실측, v2.1.287·v2.1.290·v2.1.291·v2.1.292에서 `claude plugin test` 통과.

## 알려진 한계

1. **현재 세션 한정** — 이전 세션의 요청은 조회되지 않는다. 띠 박스도 이 세션에서 플러그인이 로드된 뒤 입력한 요청부터 보여준다.
2. **Claude Code 전용** — Codex는 지원하지 않는다 (transcript 포맷이 다르다).
3. **띠 공유** — 입력창 아래 띠를 쓰는 다른 플러그인이 있으면 함께 쌓인다. 이 플러그인은 항상 다른 플러그인·엔진 힌트 줄이 그린 것 위에 박스를 둔다.
4. **mtime fallback** — 세션 ID를 얻지 못해 최근 수정 파일로 대체 탐색할 때, 같은 디렉터리에서 병렬 세션을 돌리면 다른 세션의 요청을 표시할 수 있다.

파싱 실패·파일 없음 등은 조용히 무출력으로 끝나며(exit 0), 세션 진행을 막지 않는다.

## 개발

```bash
node --test                  # /wdis 스크립트 34/34 통과
claude plugin validate .     # 매니페스트·hooks·mod 모듈 검증
claude plugin test .         # 띠 박스 mod 28/28 통과
```

- `scripts/parser.mjs` — transcript jsonl을 끝에서부터 스캔해 사용자 요청만 골라낸다 (슬래시 커맨드 래퍼·hook 주입 컨텍스트·tool_result 제외).
- `scripts/wdis.mjs` — `/wdis` 진입점. `/wdis`를 턴 0으로 처리하는 `--expand` 모드와 폴백 `--list N` 모드로 분기하고, 시간 포맷과 출력을 담당한다.
- `hooks/register.tsx` — 띠 박스 mod. `prompt.submit`에서 요청을 `$.state`에 저장하고, `ui.render`(PromptHint)에서 박스를 그린다. 상태 계약은 `types/index.d.ts`.
