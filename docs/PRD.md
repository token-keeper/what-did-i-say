# what-did-i-say — PRD

> 작성일 2026-08-09 (일) · 상태 MVP 확정 · 대상 제품 Claude Code 플러그인 `what-did-i-say` (슬래시 커맨드 `/wdis`)

## 1. 개요

### 한 줄 정의

턴이 끝나는 순간(Stop hook) **"방금 내가 요청한 프롬프트와 요청 시각"** 을 한 줄로 재표시하고, `/wdis N`으로 현재 세션의 최근 N건 요청 이력을 조회하는 Claude Code 플러그인.

조회 커맨드의 **보장 명령은 네임스페이스가 붙은 `/what-did-i-say:wdis`** 이다. bare `/wdis`는 다른 플러그인·프로젝트 커맨드와 이름이 충돌하지 않을 때만 동작하는 단축 호출이며, 문서 전반의 `/wdis` 표기는 이 단축 호출을 뜻한다.

### 배경 · 문제

Claude Code에서 한 턴이 수 분~수십 분 이어지면 화면은 도구 호출 로그와 중간 보고로 채워진다. 턴이 끝나 최종 보고가 올라온 시점에는 원래 요청문이 스크롤백 수백 줄 위로 밀려 있어, 사용자는 다음 세 가지를 반복한다.

1. 스크롤을 거슬러 올라가 자기 프롬프트를 다시 찾는다.
2. 요청을 여러 개 연달아 보낸 뒤, 지금 끝난 턴이 그중 어느 요청에 대한 응답인지 헷갈린다.
3. 자리를 비웠다 돌아왔을 때 "이 작업을 몇 분 전에 시켰는지" 감이 없어 대기 여부를 판단하지 못한다.

이 세 상황 모두 답은 이미 transcript(`~/.claude/projects/<슬러그>/<session-id>.jsonl`)에 존재한다. 사용자가 찾아 올라가는 대신, 턴 종료 시점에 제품이 먼저 보여주면 해결되는 문제다.

## 2. 목표 / 비목표

### 목표

- **G-1** 턴 종료 시 사용자 개입 없이 직전 요청문과 요청 시각을 한 줄로 자동 표시한다.
- **G-2** `/wdis N`으로 현재 세션의 최근 N건 요청을 조회한다.
- **G-3** transcript에 섞여 들어오는 비-사용자 라인(hook 주입 컨텍스트, tool_result, 서브에이전트 라인)을 요청 이력에서 제외한다.
- **G-4** 시간을 사용자 로컬 타임존 기준으로 표시하고, 경과 시간을 함께 제공한다.
- **G-5** 상태 파일 없이 동작한다 — 설치 즉시 사용 가능하고, 삭제 시 잔여물이 남지 않는다.

### 비목표 (MVP 범위 밖)

- **NG-1 Codex 지원** — MVP는 Claude Code 전용. Codex는 2단계(§6)로 분리한다.
- **NG-2 크로스 세션 조회** — 같은 프로젝트의 이전 세션 이력은 조회하지 않는다. 조회 범위는 현재 세션(`session_id`) 한정.
- **NG-3 자체 인덱스·DB·캐시 파일** — 요청 이력을 별도 저장소에 적재하지 않는다. 매 호출마다 현재 세션 jsonl을 역방향 스캔한다.
- **NG-4 요청문 검색·필터링 UI** — 키워드 검색, 태그, 즐겨찾기는 MVP에 포함하지 않는다.
- **NG-5 응답 내용 요약** — 표시 대상은 사용자 요청문이며, Claude의 응답은 다루지 않는다.

## 3. 대상 사용자 & 유저 스토리

### 대상 사용자

Claude Code로 하루 여러 시간 작업하며, 한 턴이 5분 이상 걸리는 작업(구현 위임, 대규모 리팩터, 리뷰)을 반복하는 개발자. 터미널을 주 작업 환경으로 사용하고, 여러 프로젝트 탭을 동시에 띄운 채 전환한다.

### 유저 스토리

- **US-1** As a 긴 턴을 자주 돌리는 개발자, I want to 턴이 끝날 때 내 원래 요청문이 결과 바로 아래에 다시 표시되기를, So that 스크롤을 거슬러 올라가지 않고 결과가 요청을 충족했는지 즉시 대조할 수 있다.
- **US-2** As a 요청을 연달아 여러 건 보내는 개발자, I want to `/wdis 3`으로 최근 3건의 요청과 각 요청 시각을 한 번에 조회하기를, So that 지금 끝난 턴이 어느 요청의 결과인지, 남은 요청이 무엇인지 파악할 수 있다.
- **US-3** As a 여러 프로젝트 탭을 오가는 개발자, I want to 각 요청에 `14:32 (12분 전)` 형태의 시각이 병기되기를, So that 자리를 비웠다 돌아왔을 때 이 탭의 작업이 방금 끝난 것인지 한참 전에 끝난 것인지 구분할 수 있다.

## 4. 기능 요구사항

### FR-1 Stop hook 자동 표시

- Stop hook 실행 시 stdin으로 전달되는 `session_id` · `transcript_path` · `cwd` · `stop_hook_active` JSON을 입력으로 사용한다(`stop_hook_active`는 수신만 하고 판단에 쓰지 않는다).
- `transcript_path`의 jsonl을 **파일 끝에서 역방향으로 스캔**해 필터(FR-3)를 통과하는 가장 최근 사용자 요청 1건을 확보한 즉시 스캔을 중단한다.
- stdout에 **`systemMessage` 필드를 담은 JSON 객체 하나**를 출력하며, Claude Code가 이 값을 사용자에게 표시한다.

  ```json
  {"systemMessage":"🗣 14:32 (12분 전) | 파서 필터 규칙 정리해줘"}
  ```

  hook이 stdout에 쓴 plain text는 debug log로만 전달되어 사용자 화면에 보이지 않으므로(공식 문서 확인), 표시 경로는 이 JSON 계약을 사용한다.
- `systemMessage` 값은 개행이 없는 한 줄이다. 요청문은 **CRLF/LF와 연속 공백을 단일 공백으로 collapse → 앞뒤 공백 제거(trim) → 길이 제한** 순으로 정규화한다.
- 표시는 **Stop event마다** 수행한다. 이 플러그인은 턴을 block하지 않으므로 hook 재진입 루프 위험이 없어 별도 gate를 두지 않는다.
- 조건을 충족하는 요청이 없거나 transcript 접근에 실패하면 **아무 것도 출력하지 않고 exit 0** 으로 종료한다. 플러그인 오류가 사용자 턴을 방해하지 않는다.

### FR-2 `/wdis N` 이력 조회

- 인자 없이 `/wdis` 실행 시 최근 **1건**을 표시한다(기본값).
- `/wdis N` 실행 시 최근 N건을 **시간 오름차순**(가장 최근이 마지막 줄)으로 표시한다. N이 숫자가 아니거나 1 미만이면 기본값 1로 처리한다. **상한은 100**이며, 100을 넘는 값은 100으로 보정하고 보정 사실을 한 줄 안내한다.
- 조회 범위는 현재 세션의 transcript 1개 파일에 한정한다(NG-2).
- **`/wdis` 커맨드 자신은 결과에서 제외한다** — 방금 실행한 `/wdis`(`/what-did-i-say:wdis` 래퍼 환원 결과 포함)가 목록을 차지하지 않도록 건너뛰고, 부족한 건수만큼 더 과거로 역스캔을 이어간다.
- 각 항목은 1줄로 표시한다. 형식: `[순번] 14:32 (12분 전) | <요청문 요약>` — 순번 `[1]`이 가장 최근 요청이다.
- 세션의 요청 건수가 N보다 적으면 존재하는 건수만 표시하고, 0건이면 요청 이력이 없다는 안내 1줄을 표시한다.

### FR-3 노이즈 필터

`type:"user"` 라인 중 아래 조건을 **모두** 만족하는 라인만 "요청"으로 인정한다.

| 구분 | 판정 | 근거 |
|---|---|---|
| 사용자 타이핑 원문 | **포함** | 제품이 재표시하려는 대상 그 자체 |
| 슬래시 커맨드 | **포함** (커맨드명 + 인자만 추출) | 사용자가 의도적으로 실행한 요청. 래퍼 태그와 실행 결과는 제외 |
| 슬래시 커맨드 실행 결과(`<local-command-stdout>` 등) | 제외 | 사용자 입력이 아니라 커맨드 출력 |
| hook 주입 컨텍스트(`<system-reminder>` 등) | 제외 | 시스템이 삽입한 컨텍스트 |
| tool_result 라인 | 제외 | 도구 실행 결과이며 사용자 요청이 아님 |
| 서브에이전트 라인(`isSidechain: true`) | 제외 | 메인 세션 사용자가 입력한 요청이 아님 |

- 필터를 통과한 요청문이 공백만 남는 경우 해당 라인을 이력에서 제외한다.

### FR-4 시간 표기

- 내부 계산은 **UTC 기준**으로 수행한다(jsonl의 `timestamp`는 ISO UTC).
- 표시는 **실행 환경의 로컬 타임존**을 따른다. KST 등 특정 타임존을 코드에 고정하지 않는다.
- 같은 날짜의 요청: `14:32 (12분 전)`
- 날짜가 다른 요청: 날짜를 앞에 추가한다 — `08-08 23:10 (15시간 전)`
- 경과 시간 단위: 60초 미만은 `방금`, 60분 미만은 `N분 전`, 24시간 미만은 `N시간 전`, 그 이상은 `N일 전`.

## 5. 성공 지표

성능 지표는 재현 가능하도록 **고정 벤치 픽스처 1개**를 기준으로 측정한다.

> **벤치 픽스처** `scripts/fixtures/bench-3000.jsonl` — 사용자 요청 3,000건을 포함한 총 **120,000줄 / 52,428,800바이트(50MiB)**. 생성 스크립트를 저장소에 포함해 누구나 같은 파일을 만들 수 있게 한다.

| 지표 | 목표값 | 측정 방법 |
|---|---|---|
| Stop hook 추가 지연 | **p95 100ms 미만** | 벤치 픽스처를 `transcript_path`로 준 hook 실행을 **30회** 측정한 p95 |
| `/wdis 10` 응답 시간 | **p95 300ms 미만** | 동일 벤치 픽스처에 대해 `--list 10`을 **30회** 측정한 p95 |
| 필터 오탐(비-요청이 이력에 노출) | **0건** | hook 주입·tool_result·서브에이전트 라인을 포함한 고정 픽스처 jsonl 검증 |
| 필터 미탐(실제 요청 누락) | **0건** | 타이핑 요청 + 슬래시 커맨드 혼재 픽스처 jsonl 검증 |
| 출력 줄 수 | Stop hook **개행 문자 없는 logical line 1개** (systemMessage 1건) | 긴 요청문·다중 줄바꿈 요청문 픽스처로 `systemMessage` 값에 `\n`·`\r`이 없음을 검증 |
| 상태 파일 생성 수 | **0개** | 임시 `HOME`에서 스크립트를 단독 10회 실행한 뒤 새로 생성된 파일 0개 확인 |
| 실패 시 사용자 영향 | **0건** (turn 차단 없음) | transcript 없음·손상·권한 오류 3개 케이스에서 exit 0 확인 |

## 6. 2단계 로드맵 — Codex 지원

> 2026-08-09 조사 기록(비규범) — 2단계 착수 시 재실측 후 확정한다.

MVP 검증 후 Codex 지원을 추가한다. 유력안은 **Codex 네이티브 `~/.codex/hooks.json`의 Stop 엔트리 등록**이며, 착수 시 재실측으로 확정한다.

- **근거(조사 시점 관찰)**: Codex의 `notify` 슬롯은 단일 슬롯인 데다 이미 다른 도구가 점유 중이며, 체이닝으로 연결해도 **하위 프로세스의 stdout이 터미널에 전달되지 않고 버려진다**(조사 완료). 턴 종료 시 한 줄 재표시가 이 제품의 핵심 기능이므로 notify 경로는 요구사항을 충족하지 못한다. `hooks.json`의 Stop 엔트리는 조사 당시 복수 등록이 가능했고 표시 경로도 확인되어 MVP와 같은 사용자 경험이 가능해 보였다.
- 진입 조건: MVP가 Claude Code에서 §5의 지표를 충족하고, 실사용 1주 이상 오탐 0건이 유지된 시점.
- 함께 진행할 항목: 마켓플레이스(`token-keeper/plugins`) submodule 등록.
